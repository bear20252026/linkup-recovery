| 版本 | 文件 | 大小 | 说明 |
|---|---|---|---|

公司决定：以现存安装包为基础恢复/重写整个客户端。经评估（详见第三节），该任务**可行**，但属于完整客户端重建级别的工作量，需要排期与人力投入。

## 三、技术可行性结论（关键判断）

### ✅ 能恢复的（约占客户端工作量的绝大部分）
| 内容 | 恢复程度 | 方式 |
|---|---|---|
| 界面资源/动画/文案 | 100% | 已提取，直接复用 |
| 页面结构与业务流程 | 95%+ | 反编译得到可读 Java 参考实现 |
| 网络层+签名+API 契约 | 100% | 已完整破解并有现成参考代码 |
| 数据结构/类图 | 90% | 反编译+类清单 |
| 布局 XML | 100% | apktool 文本化还原 |

### ⚠️ 无法从 APK 恢复、必须另行解决的
1. **原始源码本体**：反编译产物是"高度参考"而非原始工程，重写仍需人力
2. **后端服务端源码**：不在 APK 内；需确认服务端是否仍有存续/备份
3. **发布签名 keystore**：丢失则无法热更新旧包，需新签名重新上架
4. **三方平台账号**：微信/QQ/环信/百度地图/各推送后台的账号密码需从公司邮箱/运维处找回（SDK 配置信息本身已从 APK 提取）
5. 原始注释、CI/打包配置

### 结论
**客户端重建：可行，预计 2~6 周（2-3 名熟练 Android 开发）；后端如需重建另计。** 最大不确定性在后端数据接口的字段细节（可通过抓包老版本对齐，原服务器若仍在线则更快）。
